Most upload APIs assume a stable connection. On a 3G link in a moving vehicle or a 4G tower shared by hundreds of people, that assumption breaks constantly — and every naive implementation makes users pay for it by restarting a 20 MB upload from zero, again.

How it works

01

Chunks tracked by byte offset, not attempt.

A client asks the API where it left off and resumes from that exact byte — no chunk is ever re-sent unnecessarily.

02

Every file hashed and deduplicated on arrival.

Identical content is never stored twice, whether re-uploaded by the same user or a different one.

03

Scanning and processing off the request path.

Antivirus scanning, thumbnailing, and metadata extraction run asynchronously — your users aren't waiting on them.

Integrate in a few lines

terminal 
# 1. Create an upload session
curl -X POST https://api.ingest.dev/uploads \
  -H "Authorization: Bearer $INGEST_KEY" \
  -H "Upload-Length: 2202009"

# 2. Resume from the server-confirmed offset
curl -X PATCH https://api.ingest.dev/uploads/up_8f2a1c \
  -H "Authorization: Bearer $INGEST_KEY" \
  -H "Upload-Offset: 1583200" \
  --data-binary @remaining_chunk.bin

# 3. Query offset after a dropped connection
curl -I https://api.ingest.dev/uploads/up_8f2a1c \
  -H "Authorization: Bearer $INGEST_KEY"
# → Upload-Offset: 1583200
