Most upload clients assume the connection holds. On mobile — which is most of your users, most of the time — that assumption fails constantly. When it does, the progress bar resets to zero. Your user tries again. They blame your app for the network.

How it works

01

The server always knows the last confirmed byte.

On reconnect, the client sends a HEAD request. The server replies with the confirmed offset. The upload resumes there — not from a client-side estimate.

02

Same file, one copy.

Every upload is SHA-256 hashed on arrival. Upload the same file again and the server returns the existing object key — no bytes written.

03

Scanning runs after the upload, not before the response.

Antivirus, thumbnailing, and metadata extraction run asynchronously. The upload response comes back immediately.

Three requests. That's the protocol.

# 1. Create an upload session
curl -X POST https://api.ingest.dev/uploads \
  -H "Authorization: Bearer $INGEST_KEY" \
  -H "Upload-Length: 2202009"

# 2. Resume from the server-confirmed offset
curl -X PATCH https://api.ingest.dev/uploads/up_8f2a1c \
  -H "Authorization: Bearer $INGEST_KEY" \
  -H "Upload-Offset: 1583200" \
  --data-binary @remaining_chunk.bin

# 3. Query confirmed offset after a dropout
curl -I https://api.ingest.dev/uploads/up_8f2a1c
# → Upload-Offset: 1583200
