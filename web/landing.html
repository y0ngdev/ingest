Most upload APIs assume a stable connection. On a 3G link in a moving vehicle, or a 4G tower shared by a few hundred people, that assumption breaks constantly — and every naive implementation makes the user pay for it by restarting a 20MB upload from zero, again.

How it works

01

Chunks are tracked by byte offset, not by attempt.

A client asks the API where it left off and resumes from that exact byte — no chunk is ever re-sent unnecessarily.

02

Every file is hashed and deduplicated on arrival.

Identical content is never stored twice, whether it's re-uploaded by the same user or a different one.

03

Scanning and processing happen off the request path.

Antivirus scanning, thumbnailing, and metadata extraction run asynchronously, so your users aren't waiting on them.

Integrate in a few lines

# resume an interrupted upload from its last offset
curl -X PATCH https://api.ingest.dev/uploads/up_8f2a1c \
  -H "Authorization: Bearer $INGEST_KEY" \
  -H "Upload-Offset: 1583200" \
  --data-binary @remaining_chunk.bin
